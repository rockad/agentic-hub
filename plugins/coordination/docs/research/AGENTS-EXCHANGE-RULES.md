AGENTS EXCHANGE RULES: Cross-Device, Cross-Platform & Cross-Agent Storage Protocol
Canonical Location: Google Drive /My Drive/agents exchange
Local Symlink Standard: ~/.agents/exchange
Supported Harnesses: Claude Code (claude), Google Antigravity CLI (agy), Gemini Workspace / Web, OpenCode (opencode), Codex, and MCP-connected routers (agentic-hub / jev-router)
Supported Operating Systems: macOS, Linux (Debian / headless server), Windows 11, and Cloud/Web runtimes
1. Purpose & Scope
The agents exchange folder in Google Drive serves as the single cross-device, cross-platform, and cross-agent exchange hub for:


* Architectural Specifications & Research Audits (generated by web/cloud agents or CLI harnesses and shared across machines).
* Cross-Harness Work Handoffs & Delegations (when transitioning context between Gemini, Claude Code, Antigravity CLI, or OpenCode across devices).
* Detached Code Review Reports & Threat Models (persisted outside Git repositories so working trees and branches remain clean).
* Milestone Turn Archives & State Snapshots (portable across workstations and servers without polluting Git history).
2. Cross-Platform Mount & Access Paths
Every agent must resolve the agents exchange directory according to its runtime environment:


Platform / Runtime
	Native Path / Access Mechanism
	Recommended Local Mapping
	Cloud / Workspace Agents (Gemini, Drive MCP)
	Google Drive folder agents exchange in root (parentId = 'root')
	Query folder agents exchange via Drive search/context tools; read and write documents directly inside this folder.
	macOS (Google Drive for Desktop)
	~/Library/CloudStorage/GoogleDrive-<account>/My Drive/agents exchange
	Symlink to ~/.agents/exchange: ln -sfn "$HOME/Library/CloudStorage/GoogleDrive-"*"/My Drive/agents exchange" ~/.agents/exchange
	Linux / Debian (Headless / CLI via rclone)
	rclone remote gdrive:"agents exchange"
	Sync to ~/.agents/exchange via rclone bisync or explicit pull/push wrapper (rclone copy gdrive:"agents exchange" ~/.agents/exchange --drive-export-formats md,txt).
	Windows 11 (Google Drive for Desktop)
	G:\My Drive\agents exchange (or %USERPROFILE%\Google Drive\My Drive\agents exchange)
	Directory junction or symlink at %USERPROFILE%\.agents\exchange.
	3. File Naming & Taxonomy Conventions
All documents created inside agents exchange must use predictable, machine-parsable filenames:


* AGENTS-EXCHANGE-RULES.md — Canonical protocol specification (this file). All agents must inspect this file first when onboarding to the exchange folder.
* <project>-handoff-<topic>-<YYYY-MM-DD>.md — Active task handoffs or delegations between agents or devices (e.g., cognitive-engine-handoff-bridge-v2-2026-11-03.md).
* <project>-review-<branch-or-sha>-<YYYY-MM-DD>.md — Read-only review reports, security audits, and triage responses.
* <project>-spec-<topic>.md / <topic>-analysis.md — Architecture plans, ecosystem research, and threat models (e.g., bridge-v2-ecosystem-analysis.md).
* <project>-turns-archive.md — Consolidated milestone turn history exported from local agent bridges.
4. Mandatory Document Header Contract
Every document written to agents exchange must begin with a standardized YAML-style or bolded metadata header so parsing scripts, awk extractors, and MCP servers can route and filter documents without reading the full body:


---
project: <owner/repo or global>
author_agent: <claude-code | antigravity-cli | gemini-workspace | opencode | human>
target_agent: <claude-code | antigravity-cli | gemini-workspace | opencode | all>
host_origin: <hostname / OS | cloud>
timestamp_utc: <YYYY-MM-DDTHH:MM:SSZ>
git_branch: <branch-name or N/A>
git_head_sha: <40-char-sha or N/A>
status: <draft | ready-for-pickup | in-progress | input-required | superseded | completed>
supersedes: <filename or message-id, if applicable>
---

Strict Timestamp Rule: All timestamps (timestamp_utc, quota reset times, lease expirations) MUST be recorded in UTC ISO-8601 (Z) format. Never mix local timezones (such as EET/EEST) with UTC in shared handoff files.
5. Concurrency, Write Safety & Sync Rules
Because cloud drive synchronization (Google Drive Desktop / rclone) is eventually consistent across devices, agents must obey the following write discipline:


* Atomic Local Staging (No Partial Writes):
   * When writing to a locally mounted ~/.agents/exchange/ directory, never stream partial lines directly into the target file.
   * Build the complete file in /tmp/<filename>.tmp.$$ first, validate its header and fences, and move it into ~/.agents/exchange/<filename> in a single atomic mv operation so Drive sync sees a single close_write / moved_to event.
* Single-Writer or Append-Block Discipline:
   * Avoid simultaneous edits to the same file from two different hosts.
   * When replying to a handoff across devices or between cloud and local CLI harnesses, either:
      * Write a dedicated reply artifact (<project>-reply-<topic>-<YYYY-MM-DD>.md) referencing the parent file in supersedes / reply_to, OR
      * Append a column-0 fenced block at the bottom of the document:


---<agent> conversation <session-uuid> message <n> begin <UTC-ISO-8601>---
to: <target-agent>
about: <one-line summary>
<structured body>
---<agent> conversation <session-uuid> message <n> end <UTC-ISO-8601>---

* Google Docs vs. Raw Markdown Interoperability:
   * Workspace/Cloud Gemini agents store files in agents exchange as Google Docs with .md retained in the document title.
   * Local CLI agents pulling via Google Drive MCP (drive:download_file_content with export_mime_type: "text/plain") or rclone (--drive-export-formats md,txt) must export Google Docs as plain Markdown when syncing to ~/.agents/.
6. Security, Git Hygiene & Human-Gate Rules
* Zero Secrets Policy:
   * NEVER write API keys, OAuth tokens, .env values, private keys, passwords, or internal credentials into any file in agents exchange.
   * Any config snippet must replace sensitive values with <REDACTED>.
* Git Worktree Isolation:
   * Files in agents exchange exist specifically so agents do not pollute Git working trees with scratch handoffs. Do not commit live exchange files into feature branches unless explicitly recording a milestone Turn on a dedicated docs/ branch.
* Outward-Facing & Destructive Human Gate (status: input-required):
   * No agent may autonomously execute outward-facing or destructive operations based solely on an exchange handoff—including opening or merging GitHub PRs, git push --force, modifying global/user-scope configurations outside ~/.agents/, or altering host accounts (<storage-host>).
   * When a workflow reaches a human gate, the active agent must set status: input-required in the handoff metadata, clearly list the exact command/action awaiting approval, and pause for explicit user confirmation.
