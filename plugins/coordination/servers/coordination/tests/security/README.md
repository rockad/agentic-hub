# Security invariants suite (S1-SEC)

Master plan section "S1-SEC: security invariants suite" and `docs/specs/server-api.md` section 9, "Security invariants". Every bullet of api 9 has one row in the table below. A row names the test or tests that hold the invariant, or says why none can at stage S1.

## How to run

- `uv run pytest -q -p no:cacheprovider tests/security` from `plugins/coordination/servers/coordination`.
- The data tests use a throwaway Postgres container, the same fixture as the rest of the suite. Set `A2A_TEST_REQUIRE_DOCKER=1` so a missing Docker is a failure and not a skip (CI does).
- Nothing here starts a harness, binds port 8120 or 18120, or touches a running stack. The one Docker test that probes the network makes its own bridge network and containers and removes them.
- CI runs these files in `.github/workflows/coordination-suite.yml` across two parallel jobs: 3 security files carry `pytest.mark.hooks` (`test_no_code_path_launches_a_harness.py`, `test_readme_maps_every_api9_bullet.py`, `test_sbx_never_reaches_the_service.py`) and run in the `hooks` job, and the rest run in the `suite` job. They add no skip in a checkout. In the server image build (only `src/` and `tests/`) the tests that read `bin/`, the compose file or the spec skip.

## Files

- `test_bodies_are_data_never_logged_audited_or_woken.py`: the canary run (log, audit, other tables, wake capture, health check).
- `test_tool_results_frame_bodies_as_untrusted.py`: the untrusted frame and the server-derived origin over all nine tools.
- `test_never_approval_or_command.py`: differential test (body text changes no decision), closed tool set at the wire, no approving route or transition, parked tasks stay parked.
- `test_remote_tasks_need_a_human_release.py`: every surface while a remote task is held, then the release.
- `test_scopes_on_the_real_routes.py`: the scope matrix against the routes the real app serves.
- `test_public_host_refused_before_s3.py`: start-up refusal and runtime 421.
- `test_handle_enumeration_oracle.py`: the enumeration oracle on both A2A bindings.
- `test_agent_card_declares_only_enforced_auth.py`: the served cards against the running server.
- `test_wake_text_is_a_constant_stub.py`: every `/wake/listen` outcome, and where the stub wording lives.
- `test_status_never_opens_report_path_or_calls_out.py`: `POST /status`, no outbound client, no name of the engine.
- `test_never_exposed_on_any_endpoint_or_tool.py`: the never-exposed list.
- `test_no_code_path_launches_a_harness.py`: the static launch search, with meta-tests of the scanner.
- `test_sbx_never_reaches_the_service.py`: compose topology and the reachability probe.
- `test_readme_maps_every_api9_bullet.py`: this table is complete and every test named in it exists.
- `sec_env.py`, `sec_scan.py`: the canary run and the scanners.

## Status words

- `covered-existing`: a test in the older suite really asserts the invariant. Judged by reading it, not by its name.
- `new`: added in `tests/security/`. Each was checked to fail against a broken variant of the code (the mutation list is in the S1-SEC report, not repeated here).
- `deferred`: belongs to a later stage or stream, with the reason. Not tested here.
- `not-testable-at-S1`: a human procedure or something outside this repository, with the reason.
- A row can carry two words when part of the invariant is held by one and part by the other.

Test paths are relative to `plugins/coordination/servers/coordination/`. `T` stands for `tests/`; `S` stands for `tests/security/`.
